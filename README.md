# Compiler
Свой язык программирования
# Калькулятор выражений

Консольный REPL-калькулятор с поддержкой арифметики, скобок,
тернарного условного оператора и ограничением на значения чисел.
Построен по классической схеме: **лексер → парсер (AST) → вычислитель**.

## Возможности

- целочисленная арифметика: `+`, `-`, `*`, `/`;
- скобки для управления приоритетом: `(1 + 2) * 3`;
- тернарный оператор: `условие ? значение_если_истина : значение_если_ложь`;
- ограничение `LIMIT` на числа и результаты операций;
- дружелюбные сообщения об ошибках вместо паник;
- REPL-цикл: команды читаются со стандартного ввода, `exit` — выход.

## Структура проекта

```
src/
  main.rs   — весь код: лексер, парсер, вычислитель, REPL
```

## Как это работает

### 1. Токены (Token)

Входная строка разбивается на минимальные единицы — токены:

| Токен             | Описание                          |
|-------------------|-----------------------------------|
| `Number(i64)`     | целое число, например `42`        |
| `Plus`, `Minus`   | `+` и `-`                         |
| `Multiply`, `Divide` | `*` и `/`                      |
| `LParen`, `RParen`| скобки `(` и `)`                  |
| `Question`, `Colon` | `?` и `:` для тернарного оператора |
| `EOF`             | конец ввода                       |

Пример: строка `1 + 2 * 3` превращается в последовательность
`[Number(1), Plus, Number(2), Multiply, Number(3)]`.

### 2. Лексер (Lexer)

`Lexer::next_token()` читает вход посимвольно:

1. пропускает пробельные символы (`skip_whitespace`);
2. одиночные символы (`+`, `-`, `*`, `/`, `(`, `)`, `?`, `:`) превращаются в токены напрямую;
3. цифра запускает чтение целого числа: символы накапливаются по формуле
   `num = num * 10 + цифра`;
4. всё остальное — ошибка («Неожиданный символ: …»).

Два защитных механизма на этапе чтения числа:

- `checked_mul` / `checked_add` — переполнение `i64` при накоплении цифр
  возвращает ошибку, а не «заворачивает» число по модулю;
- `check(num)` — литерал сразу сверяется с константой `LIMIT`.

### 3. Парсер (Parser)

Рекурсивный спуск. Приоритет операторов задаётся уровнями функций —
каждый уровень обрабатывает свои операторы и опирается на следующий,
более приоритетный:

```
ternary   (низший приоритет)  — `? :`
  expr     (сложение/вычитание) — `+ -`
    term     (умножение/деление) — `* /`
      factor   (высший) — число или `(ternary)`
```

- `ternary()`: разбирает левую часть (`expr`), затем, если видит `?`,
  читает `then`-ветвь, ждёт `:` и читает `else`-ветвь. Вызов `ternary`
  для обеих ветвей даёт **правую ассоциативность**:
  `a ? b : c ? d : e` = `a ? b : (c ? d : e)`.
- `expr()` и `term()` строят цепочки бинарных операций в цикле,
  поэтому `1 + 2 + 3` разбирается как `(1 + 2) + 3` (левая ассоциативность).
- `factor()` — база рекурсии: число либо выражение в скобках; внутри
  скобок снова доступен тернарный оператор, поэтому `(2 ? 1 : 0) ? 10 : 20`
  работает.

Результат — дерево выражений (AST):

```rust
enum Expr {
    Number(i64),
    BinaryOp { left: Box<Expr>, op: Token, right: Box<Expr> },
    Ternary  { cond: Box<Expr>, then_branch: Box<Expr>, else_branch: Box<Expr> },
}
```

`Box` нужен, потому что `Expr` рекурсивен: узел содержит другие узлы,
размер которых на этапе компиляции неизвестен.

### 4. Вычислитель (eval)

Обходит AST и возвращает `Result<i64, String>` — ошибки собираются
и поднимаются вверх через `?`, не приводя программу к панике.

- **Тернарный узел** вычисляется лениво: сначала `cond`, затем только
  выбранная ветвь. Если условие истинно (`≠ 0`) — `then`, иначе — `else`.
  Неправильная ветвь не вычисляется, поэтому `1 ? 5 : 1/0` вернёт `5`,
  а не ошибку деления на ноль. Условие числовое: `0` — ложь.
- **Бинарные операции** используют `checked_add` / `checked_sub` /
  `checked_mul` — переполнение превращается в понятную ошибку.
  Для деления отдельные проверки: на ноль и на единственный
  некомпьютаемый случай `i64::MIN / -1`.
- После каждой операции результат проходит через `check(x)`:
  значения по модулю больше `LIMIT` отклоняются.

### 5. Ограничение LIMIT

```rust
const LIMIT: i64 = i64::MAX; // по умолчанию — без ограничения
```

Константа задаёт верхнюю границу и для литералов, и для промежуточных,
и для итоговых значений. Например, при `LIMIT = 999_999` выражение
`1000 * 1001` даст ошибку «Выход за пределы ограничения», хотя само
по себе оно умещается в `i64`. Чтобы ужесточить лимит, достаточно
изменить значение константы.

### 6. REPL (main)

Главный цикл:

1. печатает приглашение `> ` и сбрасывает буфер вывода;
2. читает строку; пустая — просто переходит к следующей итерации;
3. `exit` — завершает программу;
4. строка проходит путь: `tokenize` → `Parser::parse` → `eval`;
5. ошибки любого этапа выводятся в виде `Ошибка: …`, REPL продолжает работу.

## Приоритет операторов (от низшего к высшему)

1. `? :` — тернарный (правая ассоциативность);
2. `+`, `-`;
3. `*`, `/`;
4. числа и скобки.

## Примеры

```
> 2 + 2
= 4
> (1 + 2) * 3
= 9
> 10 / 4
= 2
> 1 ? 100 : 200
= 100
> 0 ? 100 : 200 + 300
= 500
> 1 ? 5 : 1 / 0
= 5
> 2 ? 1 : 0 ? 7 : 8
= 7
> 9223372036854775807 + 1
Ошибка: Переполнение при вычислении 9223372036854775807 Plus 1
> 5 / 0
Ошибка: Деление на ноль
> exit
```

## Сборка и запуск

```bash
cargo run
```
